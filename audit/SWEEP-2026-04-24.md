## CHROME — deck-level (one fix solves many)

The page chrome (NORMAL / SLIDE SHOW / PRESENTER / DUAL SCREEN buttons +
page indicator + arrows) renders **on top of** the slide footer. Any
slide whose footer sits in the bottom ~80 px gets sliced.

Confirmed affected: 02, 03, 06, 09, 14, 19, 20, 22, 26, 29.

Fix path: reserve a `--chrome-safe` bottom inset in SlideGrid so footers
never lay underneath chrome. Predictable layout, no animation race.

## Universal-defaults audit (zaj-slides skill)

- **Font-size floor (14pt = ~18.7px).** Grep for `fontSize:` values below
  14px in JSX → **0 matches**. ✅
- **`{{VERIFY}}` / TODO / FIXME placeholders.** → **0 matches**. ✅
- **prefers-reduced-motion.** Centralized at
  `src/lib/motion.js:67` (`useReducedMotionPref`). Slides that gate
  shared-element layoutId on this hook: confirmed for lung (5/6),
  analysis-plot (10/11/12), approval timeline (7/13). ✅
- **Canvas discipline.** SlideGrid uses `100dvh` + `overflow: hidden` +
  CSS Grid named areas. Doesn't enforce 1920×1080 strict (this is a React
  deck running in browser viewport, not a fixed-canvas HTML deck), but
  named-area grid prevents structural overlaps. The visual issues above
  all live INSIDE the `viz` row's contents, not at the chrome level. ✅
  (CHROME issue is a separate inset bug, not a canvas-discipline bug.)
